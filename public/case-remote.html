Case Study 05

Remote GUI

把偏工程的遠端控制、狀態判讀與指令執行，轉成現場人員能在觸控螢幕上安全操作的 Linux GUI。

Remote Control 工業 GUI 高風險操作 狀態燈號 虛擬鍵盤

01

Context

專案背景

Remote GUI 用於現場設備的遠端控制與維護，包含查看系統狀態、執行指令、檔案管理、設備重啟與確認連線模式。使用者不只有工程師，也包含技術服務與現場維護人員。

這次設計延續既有網頁版的綠色配色與控制語言，轉成 Linux 現場觸控畫面。現場設備沒有鍵盤，也可能在強光或昏暗環境中操作，因此畫面需要高對比、清楚文字、明確按鈕回饋與可啟閉的虛擬鍵盤。

02

Needs & Pain Points

現場操作與安全痛點

畫面不只要顯示資料，還必須在受限硬體與不穩定環境中，幫助非工程使用者安全地送出控制指令。

操作偏工程

執行指令、設備重啟與連線模式確認都偏技術，需要把工程語言轉成使用者能判斷的狀態與下一步。

高風險操作

閘門操作、指令執行與重啟設備都可能影響現場安全，需要在動作前說清楚後果並要求確認。

狀態燈號差異大

不同站點的燈號數量與名稱不固定，版面需要依尺寸調整文字與排列，並用分頁承接更多狀態。

現場光線不穩定

設備可能在強日光或昏暗環境下使用，單靠顏色不夠，需要同時用文字標籤與明顯按鈕狀態輔助判讀。

設定類別多

控制、設定與維護功能混在一起時容易誤觸，需要用 tab 或分區整理，預設先露出常用操作。

03

Design Strategy

設計策略

我先用 wireframe 確認實際操作順序，拆出常用操作、危險動作、二次確認條件，以及沒有鍵盤時的輸入情境。接著把狀態燈號、閘門控制、輔助控制與連線模式放在同一個主畫面。

視覺上延續既有網頁版的綠色主色、狀態燈號與大型控制元件，再加入工業現場需要的高對比按鈕、清楚分頁與大字警示。介面重點是讓使用者知道目前狀態、操作目標與按下去之後會發生什麼事。

這不是單純把網頁版改成工業風，而是保留原本的狀態與控制語言，再依 Linux 現場設備的觸控、鍵盤與安全限制重新組織。

  • 先理流程：wireframe 階段先和工程師對齊操作路徑、確認條件與設備回饋。
  • 同頁判讀：將即時數值、狀態燈號、閘門控制與輔助控制集中在主操作頁。
  • 防止誤觸：危險動作使用大字警示與確認視窗，必要時搭配虛擬鍵盤輸入。
04

Key Screens & Outcomes

主要畫面、設計重點與成果

註：部分畫面已去識別化處理，僅用於呈現設計流程、資訊架構與介面結構。

從網頁版到 Linux 現場版

設計重點：保留綠色主色、狀態燈號與大型控制元件，重組為 1024x768 現場觸控畫面。

形成的結果：使用者可沿用熟悉的判讀方式，同時適應 Linux 設備的觸控與現場限制。

參數設定與輸入回饋

設計重點：將點位、公式與初始值整理為明確欄位，同時呈現錯誤輸入的狀態。

形成的結果：工程與現場人員能在儲存前發現格式問題，降低錯誤參數影響設備的風險。

高風險確認視窗

設計重點：在偵測到危險區人員時，以大字警告、攝影機名稱與兩個明確動作要求操作者再次判斷。

形成的結果：危險動作不會因單次誤觸立即執行，操作者也知道確認前必須先檢查什麼。

可啟閉虛擬鍵盤

設計重點：輸入數值時開啟大型觸控鍵盤，並提供刪除、取消與確認的高對比動作。

形成的結果：無實體鍵盤的現場設備仍能完成輸入，鍵盤也不會在非輸入任務時遮擋操作畫面。

Project Information

專案資訊

Role

我的角色

負責 wireframe / flow、Linux GUI、狀態燈號、控制路徑、虛擬鍵盤與高風險操作防呆。

Users

主要使用者

公司內部工程師、技術服務部、PM、客戶現場維護人員，以及管理處人員。

Scope

涵蓋範圍

即時數值、狀態燈號、閘門與輔助控制、參數設定、高風險確認視窗與虛擬鍵盤。
